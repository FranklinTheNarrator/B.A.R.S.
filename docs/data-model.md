## 1. Словарь проекта

| Термин курса | Термин моей темы |
|---|---|
| Ticket | наблюдение (замер состояния) |
| Site | справочник состояний |
| User | оператор / аналитик / руководитель |

## 2. Сущности и поля

### 2.1. StateType (справочник состояний)

| Поле | Тип | Ключ |
|---|---|---|
| id | int | PK |
| name | string | — |
| description | string | — |

Примеры записей: `Sleepy`, `Happy`, `Angry`, `Neutral`, `Stressed`.

### 2.2. Observation (главный объект — наблюдение)

| Поле | Тип | Ключ |
|---|---|---|
| id | int | PK |
| number | string | — |
| title | string | — |
| description | string | — |
| confidence | decimal | — |
| status | string | — |
| stateTypeId | int? | FK → StateType.id, пока ИИ не отработал — пусто |
| employeeId | int | FK → Employee.id |
| createdByUserId | int | FK → User.id |
| assigneeUserId | int? | FK → User.id, может быть пустым |

### 2.3. Employee (сотрудник)

| Поле | Тип | Ключ |
|---|---|---|
| id | int | PK |
| fullName | string | — |
| department | string | — |

### 2.4. User (пользователь системы)

| Поле | Тип | Ключ |
|---|---|---|
| id | int | PK |
| login | string | — |
| fullName | string | — |
| role | string | — |

## 3. Связи

- один справочник (StateType) - много наблюдений;
- один сотрудник — много наблюдений;
- один пользователь создаёт много наблюдений;
- один пользователь может быть назначен на много наблюдений;
- у нового наблюдения исполнитель и определённое состояние могут отсутствовать.

## 4. Проверка 3НФ

Название состояния хранится в сущности StateType один раз. Observation содержит внешний ключ stateTypeId. При переименовании состояния меняется одна строка, поэтому текст названия не дублируется в наблюдениях.

## 5. Роли и права

| Роль | Создаёт наблюдение | Запускает анализ ИИ | Меняет статус наблюдения |
|---|---|---|---|
| Оператор | да | да | нет |
| Аналитик | нет | нет | да (только своё) |
| Руководитель | нет | да | нет |
