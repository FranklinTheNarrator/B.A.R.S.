## Предметная область

Заказчик — отдел маркетинга ООО «1С-Франчайзи». Процесс - обработка внутренних заявок на маркетинговые исследования (анализ рынка, опрос клиентов, фокус-группа, конкурентный анализ). Сейчас заявки приходят в чат и на почту, теряются, и через неделю невозможно понять, кто взял работу и на какой стадии она находится. Одна актуальная запись в системе заменяет переписку и позволяет видеть статус каждой заявки и ответственного исполнителя.

## Как есть

Руководитель отдела маркетинга пишет в рабочий чат: «Нужно исследование по сегменту B2B». Кто-то из маркетологов отвечает, что возьмёт. Через день выясняется, что задачу видели двое, но никто не начал. Ещё через день заявка всплывает снова, потому что руководитель забыл, кому её отдал. Маркетолог уходит в отпуск — заявка «висит». Отчёт по исследованию приходит в личку, а не в общий доступ. Через неделю никто не может сказать, сколько заявок в работе, сколько закрыто и кто за что отвечает. Приходится поднимать историю чата вручную.

## Как будет

Одна запись - **заявка на маркетинговое исследование**. Заказчик (руководитель отдела или продакт-менеджер) создаёт заявку: заголовок, вид исследования из справочника, описание. Руководитель отдела маркетинга назначает маркетолога-аналитика отдельным действием. Аналитик берёт заявку в работу, меняет статус по мере выполнения и закрывает её. В списке заявок видно: номер, заголовок, вид исследования, исполнитель, статус, дата создания.

## Граница

**Внутри:** главный объект (заявка на исследование), справочник видов исследований, назначение исполнителя, смена статуса, три экрана (список, создание, вход), сохранение в PostgreSQL.

**Снаружи:** интеграция с 1С:Управление маркетингом, автоматический расчёт ёмкости сегмента, экспорт отчётов в PDF/Excel, SMS- и email-уведомления, мобильное приложение, SSO/LDAP, аналитический дашборд руководителя.

## Роли

| Роль | Создаёт | Назначает исполнителя | Меняет статус |
|------|---------|------------------------|---------------|
| Заказчик (руководитель отдела / продакт) | да | нет | нет |
| Руководитель отдела маркетинга | нет | да | нет |
| Маркетолог-аналитик (исполнитель) | нет | нет | да (только свою) |

Правило курса: кто создаёт — не тот, кто закрывает чужую запись. Исполнитель двигает **только свою**.

## Функциональные требования

- **ФТ-1.** Заказчик может создать заявку: заголовок, вид исследования (ссылка числом), описание. После успеха видит новую запись со статусом `New` и человеческим номером.
- **ФТ-2.** Руководитель отдела маркетинга видит список всех заявок с фильтром по статусу и исполнителю.
- **ФТ-3.** Руководитель может назначить исполнителя на заявку в статусе `New` отдельным действием, не меняя статус.
- **ФТ-4.** Назначенный исполнитель видит свои заявки в отдельном списке «Мои заявки».
- **ФТ-5.** Исполнитель может перевести свою заявку `New` → `InProgress`.
- **ФТ-6.** Исполнитель может перевести свою заявку `InProgress` → `Closed`.
- **ФТ-7.** Исполнитель может отменить свою заявку: `New`/`InProgress` → `Cancelled`.
- **ФТ-8.** **Запрет:** исполнитель не может менять статус чужой заявки (система возвращает 403 и не отображает кнопку).
- **ФТ-9.** **Запрет:** заказчик не может назначать исполнителя и менять статус.
- **ФТ-10.** **Запрет:** руководитель не может создавать заявку от имени заказчика.
- **ФТ-11.** Валидация при создании: заголовок 5–80 символов, `researchTypeId` > 0, описание 10–500 символов.
- **ФТ-12.** При создании система автоматически присваивает человеческий номер вида `MR-ГГГГ-NNNN`.

## Нефункциональные требования

- **НФТ-1.** После перезапуска сервера созданные записи на месте (данные в PostgreSQL, не в памяти).
- **НФТ-2.** API отвечает на запрос списка заявок не дольше 1 секунды при 1000 записей.
- **НФТ-3.** Пароли хранятся в виде хеша (bcrypt/argon2), не в открытом виде.
- **НФТ-4.** Все ошибки API возвращают JSON с кодом и сообщением; фронтенд показывает понятный текст пользователю.
- **НФТ-5.** Интерфейс работает в браузерах Chrome, Firefox, Edge последних версий.

## Пользовательские истории (кратко)

- Как **заказчик** хочу создать заявку на исследование, чтобы не писать в чат и не терять её.
- Как **руководитель отдела маркетинга** хочу назначить исполнителя, чтобы было понятно, кто отвечает за заявку.
- Как **маркетолог-аналитик** хочу видеть свои заявки и менять их статус, чтобы руководитель видел прогресс.
- Как **руководитель** хочу видеть список всех заявок с фильтром, чтобы понимать загрузку отдела.

## Сценарий использования (use case) — минимум один целиком

| Поле | Содержание |
|------|------------|
| Название | Создание заявки на маркетинговое исследование |
| Актёр | Заказчик (руководитель отдела / продакт) |
| Предусловие | Пользователь аутентифицирован, роль — «Заказчик». Справочник видов исследований заполнен. |
| Основной поток | 1) Заказчик открывает экран «Создать заявку». 2) Выбирает вид исследования из справочника. 3) Вводит заголовок (5–80) и описание (10–500). 4) Нажимает «Создать». 5) Система валидирует поля, генерирует `number` и `id`, сохраняет запись со статусом `New`. 6) Заказчик видит созданную заявку в списке. |
| Альтернатива | Если заголовок или описание не проходят валидацию, система подсвечивает поле и не сохраняет запись. Если не выбран вид исследования — кнопка «Создать» неактивна. |
| Постусловие | В БД есть новая запись со статусом `New`, человеческим номером и ссылкой `researchTypeId`. Заявка видна руководителю для назначения исполнителя. |

## Обязательные до курсовой (критерии приёмки)

### 1. Создать объект

**Дано:** заказчик вошёл в систему.  
**Когда:** заполняет заголовок (5–80), ссылку на справочник числом (> 0), описание (10–500) и нажимает «Создать».  
**Тогда:** появляется запись со статусом «Новая» (`New`) и человеческим номером `MR-ГГГГ-NNNN`. Да / нет.

### 2. Назначить исполнителя

**Дано:** руководитель отдела маркетинга и запись в статусе `New`.  
**Когда:** назначает исполнителя отдельным действием (не вместе со статусом).  
**Тогда:** у записи есть исполнитель; статус ещё можно не менять. Да / нет.

### 3. Исполнитель перевёл в работу

**Дано:** назначенный исполнитель вошёл.  
**Когда:** он переводит свою запись `New` → `InProgress`.  
**Тогда:** статус «В работе»; чужой логин ту же запись не двигает. Да / нет.
